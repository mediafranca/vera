# Vera 0.7.3 — Desktop vuelve a abrir la memoria existente

> **Corte no publicado.** La matriz detuvo el DMG universal al encontrar los
> binarios nativos de ambas arquitecturas sin una regla explícita de unión. La
> corrección se publica con un número nuevo en Vera 0.7.4; este tag no se mueve
> ni se reutiliza.

Este corte corrige dos bloqueos de arranque observados al actualizar Vera
Desktop. Ninguno exige reemplazar, borrar ni volver a constituir la biblioteca.

## Paquete de ejecución completo

- cada instalador lleva `@napi-rs/canvas` y el binario nativo de su plataforma;
- macOS universal se comprueba para Apple Silicon e Intel, no sólo para la
  arquitectura de la máquina que construye;
- el lector PDF se carga únicamente al importar un PDF, de modo que una
  capacidad secundaria no puede dejar la aplicación completa en blanco;
- el actualizador admite las dos formas de carga del módulo CommonJS y, si no
  está disponible, se desactiva sin impedir abrir la memoria;
- la matriz de GitHub verifica el contenido real de `app.asar` antes de publicar
  artefactos de Windows, macOS o Linux.

## Migración tolerante

- la migración 25 reconoce bibliotecas que ya contienen `participant_id` en sus
  invitaciones y conserva sus filas;
- una columna que ya existe deja de convertir la actualización en una pantalla
  blanca;
- la migración continúa siendo transaccional: un fallo revierte el paso sin
  alterar la biblioteca de origen.

## Verificación

- regresiones de empaquetado, carga diferida de PDF y migración sobre esquemas
  parcialmente adelantados;
- inspección del paquete Linux construido localmente, incluyendo puente y
  binario nativo;
- typecheck, especificaciones Allium, trazabilidad, build web y suite completa
  antes de publicar.
